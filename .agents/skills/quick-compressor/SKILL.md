# Quick Compressor 開発・ビルド・リリースガイド

本プロジェクト「Quick Compressor」の開発、ビルド、およびリリース作業を安全かつ正確に進めるためのルールと指示書です。作業を開始する前に、必ず本ドキュメントの内容を確認し、以下の手順と設計思想に従ってください。

---

## 📖 コードマップ（最初に確認）

**`main.py` は約 3,500 行の大規模ファイルです。**
全体構造を把握するための詳細なリファレンスが `CODE_MAP.md` に存在します。
`main.py` を読む前に必ず `CODE_MAP.md` を参照し、トークンの無駄遣いを防いでください。

| ファイル | 役割 |
|---------|------|
| `CODE_MAP.md` | `main.py` の全セクション・メソッド・行番号・処理フローを網羅したリファレンス |
| `main.py` | メインアプリ本体（GUI・変換処理・プリセット管理など全て） |
| `register_menu.py` | Windows レジストリへの右クリックメニュー登録・解除、`APP_DIR` / `DATA_DIR` の定義 |
| `default_presets.json` | 同梱のデフォルトプリセット定義（AMD 環境では起動時に NVIDIA 表記を AMD に置換） |

> **使い方**: 「〇〇の処理を変えたい」と思ったら、まず `CODE_MAP.md` の目次で該当行番号を探し、その行だけ `main.py` を確認してください。

## 🚨 AI 共通ルール

1. **インストールの事前確認**:
   何かツールやライブラリをインストールする前に、必ず `where` コマンド（Windows環境では `where.exe`）を実行し、すでにインストールされていないか確認してください。
2. **日本語でのコミュニケーション**:
   ユーザーへの回答や説明は常に日本語で行ってください。
3. **方針の確認と精度の向上**:
   ユーザーが方針に迷っている場合や、要望が曖昧な場合は、必ず質問をして精度を向上させてください。また、可能な限り複数の選択肢を提示してください。
4. **自動コミット・プッシュ・ビルドの禁止**:
   ソースコードの修正やファイルの変更を行った際、作業のたびに毎回自動で `git commit`, `git push`、およびビルド（`build.bat`など）を実行するのは禁止です。コードの修正が完了した時点では、ユーザーに完了を報告するのみとし、**ユーザーから明示的な指示があった場合にのみ**実行してください。

## 🛠️ プロジェクトの設計ルール

1. **実行ファイルのパス解決 (`sys.frozen`)**:
   - アプリケーションが PyInstaller によって .exe 化されている場合（`getattr(sys, 'frozen', False)` が真）、実行ファイルと同じ階層からファイルをロードするよう、動的にパスを解決してください。
   - `APP_DIR`（アプリのある場所）の解決は `main.py` の `get_app_dir()` 関数が行います。
2. **書き込み制限の回避 (%APPDATA%)**:
   - `C:\Program Files` などの保護されたディレクトリにインストールされた際、書き込みエラーを避けるため、ユーザー設定（`presets.json`）や動作ログ、アップデートキャッシュ（`config.json`）などは必ず `%APPDATA%\QuickCompressor` に保存してください。
   - このパスは `register_menu.DATA_DIR` として定義されています。`main.py` 内では `register_menu.DATA_DIR` を参照する形で統一してください。
3. **右クリックメニューの登録・解除**:
   - 右クリックメニューの登録・解除は `main.py` に引数 `--register` / `--unregister` を渡すことで行います。これは、Inno Setupインストーラーがインストール・アンインストール時に自動で呼べるようにするためです。
   - 実際の登録処理は `register_menu.register_context_menu()` / `register_menu.unregister_context_menu()` が担います。
4. **自動アップデート検知とAPI制限対策**:
   - 起動時に非同期（`daemon=True` スレッド）で GitHub Releases API (`https://api.github.com/repos/LunaFleuret/Quick-Compressor/releases/latest`) を確認します。
   - 同一IPアドレスからの過剰アクセスによるAPI制限を防ぐため、確認日時のタイムスタンプを `%APPDATA%\QuickCompressor\config.json` に保存し、**24時間に1回のみ**通信するようにキャッシュ処理を行ってください。
   - インターネット未接続時やAPI制限エラー(403)時は、エラーダイアログを出さずに静かに処理をスルー（サイレントスルー）し、タイムスタンプだけ記録してください。
5. **GPUの自動判別と初期設定**:
   - 初回設定作成時（`presets.json` がローカルに存在しない場合）、自動的にGPUを判別し、`default_presets.json` のコーデック指定（例: NVIDIA NVENC）を環境に合わせて最適化（AMD AMF 等に置換）してから保存します。ユーザーが既に設定ファイルを持っている場合は上書き・変更を行いません。
   - GPU 判別は `register_menu.is_amd_gpu()` で行っています。
6. **プリセットデータ形式 (UUID キー)**:
   - `presets.json` のキーは必ず `str(uuid.uuid4())` で生成した UUID 文字列にしてください。
   - 旧形式（プリセット名がキー）のファイルを読み込んだ場合は、`_get_user_presets()` 内の自動マイグレーション処理で UUID キーに変換します（バックアップ `.bak` ファイルも作成）。
   - デフォルトプリセット（`default_presets.json` 由来）は書き込み保護扱いとし、名前変更・削除・上書き保存を禁止してください。

## 🐛 デバッグ・コード実装の安全基準

1. **UIスレッドの安全性 (Tkinter)**:
   - FFmpegの実行など重い処理をバックグラウンドスレッドで実行する場合、プログレスバーやステータスラベルなどのUI更新は、必ず `self.root.after(0, lambda: ...)` を使用してメインスレッドに委譲してください。別スレッドから直接UIを操作するとフリーズやクラッシュの原因になります。
2. **サブプロセス実行時の文字化け・デッドロック対策**:
   - `subprocess.Popen` や `subprocess.run` を実行する際は、全角文字（日本語のファイルパスなど）による `UnicodeDecodeError` を防ぐため、必ず引数に `encoding="utf-8", errors="replace"` を指定してください。
   - OSのパイプバッファ詰まりによるデッドロック（フリーズ）を防ぐため、処理内で読み取らない不要な標準出力 (`stdout`) は `subprocess.PIPE` ではなく `subprocess.DEVNULL` に設定してください。
   - コンソールウィンドウが表示されないよう、常に `creationflags=subprocess.CREATE_NO_WINDOW` を付けてください。
3. **テスト・デバッグ用ファイルの隔離**:
   - 動作検証に使用する動画ファイルや一時スクリプト（`test_runner.py`など）、実行ログなどは、必ず `デバッグ用/` などの専用フォルダに格納し、本番のソースツリーを汚さないようにしてください。
4. **FFmpegフォールバック処理**:
   - GPU エンコーダーは環境によっては動作しない場合があります。`_run_ffmpeg()` には自動フォールバック機構があります（AV1→HEVC→H.264 の順）。
   - 新しいエンコーダーを追加する場合は、このフォールバックチェーン（`_run_ffmpeg` の `elapsed_time < 2.0` 判定部分）を壊さないよう注意してください。
5. **`config.json` の読み書き**:
   - `config.json` への書き込みは、既存データを読んでから必要なキーだけ上書きする方式（マージ）にしてください。まるごと上書きすると他のキー（統計データや更新チェック日時など）が消えます。
   - 参考実装: `_save_app_config()` メソッドを参照してください。

## 📦 Git・GitHub 運用ルール

1. **不要なファイルの除外**:
   - 容量の大きいビルド生成物や、FFmpegバイナリなどは絶対に Git に含めないでください。
   - `.gitignore` に以下のディレクトリとファイルが正しく登録されていることを確認してください。
     - `build/`、`dist/`、`Output/`、`*.spec`
     - `user_presets.json`、`presets.json`
     - `bin/`（FFmpeg / FFprobe バイナリ）
     - `デバッグ用/`（検証用ファイル・スクリプトの一時置き場）
     - `CODE_MAP.md`（AIリファレンス、ローカル専用）

## 🏗️ ビルドとインストーラー作成・リリース手順

1. **ビルドの実行**:
   プロジェクト直下の `build.bat` を実行してください。
   - これにより、PyInstallerによる `.exe` 化から、Inno Setup (ISCC.exe) によるインストーラー (`Output/QuickCompressor_Setup.exe`) の作成までが全自動で行われます。
   - ※注意: フォルダ内に `dist/bin` を作成し、そこに `ffmpeg.exe` と `ffprobe.exe` が事前に配置されている必要があります（一度配置すれば次回以降はそのまま使えます）。
2. **バージョン番号の更新**:
   - `main.py` の `CURRENT_VERSION` 定数を更新してください（例: `"2.0.1"` → `"2.1.0"`）。
   - Inno Setup のスクリプトにもバージョン番号が記載されている場合は、同時に更新してください。
3. **GitHub Releases での公開**:
   - リリースタグ名は必ず **`vX.X.X`**（例：`v2.0.1`）の形式にしてください（アプリの自動アップデート検知のパース処理と整合させるため）。
   - Assets エリアには、必ずビルドした **`Output/QuickCompressor_Setup.exe`** を手動でアップロードしてください。
